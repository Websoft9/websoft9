我的应用 · 数据 · 数据库 — UI 设计预览

目标：一条记录展示一个可用连接，字段与真实数据一致；空值不误导。以下为两种展示口径，各含「显示一个」与「显示多个」两种形态。 示例数据来自本机实例（WordPress、Drupal）与模板声明（Seafile、Dify）。

方案 A · 单表平铺（沿用现有表格）

改动最小：保留现有表头与行样式，只把数据源换成接口返回值，并新增「数据库名称」列。多账号、多库时自动多行。

方案 B · 实例分组卡（一个实例一张卡）

按「数据库实例」分组：卡头放类型、地址；卡内先列库名，再用小表列账号。多实例时不再重复地址，层级更清楚，但结构改动比方案 A 大。

方案对比

维度 方案 A · 单表平铺 方案 B · 实例分组卡
改动量 小：沿用现有表头与行样式，替换数据源、加两列 中：新增实例卡片结构与样式，现有表格样式保留给账号行
显示一个 一行，信息完整、密度高 一张卡，地址与状态更醒目
多个账号 多行，地址与库名重复 同卡内多行账号，地址只出现一次
多个实例 多行，需靠「数据库」列区分 多卡，天然分组，地址只出现一次
与现有 UI 一致性 高 中：卡片层级是新增的视觉元素
建议 先做这一版，覆盖当前 50 个应用 后续应用出现多实例（如 Dify）时再升级

共同规则：空值显示「—」且不渲染掩码与复制按钮；内置库地址标注「仅容器网络内可连」；按钮保持直角。
