设计说明

  1. 两种地址必须同时出现：数据库应用的「访问」页签目前只回答「外部怎么连」，而平台内应用（如 WordPress 连外部 MySQL）需要容器网络地址，这也是两个页签口径不一致的根源。
  2. 端口要标注映射关系：`9001` 是宿主机映射端口，容器内监听 `3306`；不写清楚会让用户把 9001 当成 MySQL 端口。
  3. 数据来源复用现有接口：平台内地址/端口/库名/账号来自 `GET /api/apps/{app_id}/databases`（类型字典 + 容器名 + 停机回退 compose），外部地址沿用现有 `*_PORT_SET` 逻辑，无需新增后端能力。
  4. 凭证不重复、只增强：现有用户名/密码/复制/显隐保留，新增默认库、驱动、字符集与 `.env` 片段复制；密码仍默认掩码。
  5. 停机可用：应用停止时容器环境读不到，地址回退到 compose 的 `container_name`，两栏仍可展示（与「数据」页签一致）。
