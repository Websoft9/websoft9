# Custom Application Development

Websoft9 loads locally developed Docker Compose applications from `${WEBSOFT9_DATA_ROOT}/localapps`. The default location is `/opt/websoft9/data/localapps`.

```text
localapps/
├── catalog/                         # Edit: App Store display metadata
│   └── affine.json
├── apps/                            # Edit: deployment templates
│   └── affine/
│       ├── .env
│       ├── docker-compose.yml
│       ├── variables.json
│       ├── .env.external-db         # Optional deployment profile
│       └── src/                     # Optional files mounted by Compose
└── manifest/                        # Generated: do not edit
    └── app-store-manifest.json
```

`catalog/` and `apps/` are source directories. `manifest/` is generated by the refresh action and can be rebuilt at any time. Do not put application secrets in `catalog/` or edit the manifest directly.

## Create an Application

Choose a lowercase application key using letters, digits, and hyphens, for example `affine`. Its metadata and deployment directory must use the same key:

```text
catalog/affine.json
apps/affine/
```

The following three files are required. An application missing any one of them is skipped during refresh.

### `catalog/<key>.json`

This file controls App Store presentation. `trademark`, `summary`, `overview`, `description`, `websiteurl`, and `screenshots` are optional but recommended.

```json
{
  "trademark": "Example App",
  "summary": "A short description shown in the App Store.",
  "overview": "A longer introduction to the application.",
  "websiteurl": "https://example.com",
  "screenshots": ["https://example.com/screenshot.png"],
  "catalogBindings": [
    { "parentKey": "productivity", "childKey": "whiteboard" }
  ]
}
```

Use official catalog identifiers in `catalogBindings`. The App Store resolves these keys using its existing catalog data, so local applications participate in the same category filters as marketplace applications.

### `apps/<key>/.env`

Use this file for Compose variables. Variables named `W9_*_SET` are exposed as install settings. Define `W9_URL` for a web application and use `W9_HTTP_PORT_SET` for its exposed port.

```dotenv
W9_HTTP_PORT_SET=8080
W9_URL=http://${W9_DOMAIN}:${W9_HTTP_PORT_SET}
APP_PASSWORD=replace-before-production
```

Keep production secrets out of shared templates. Set unique values before installation.

### `apps/<key>/docker-compose.yml`

Provide a standard Docker Compose file. Reference values from `.env` with `${VARIABLE}`. Define named volumes for state that belongs to the application.

```yaml
services:
  example:
    image: example/image:latest
    ports:
      - "${W9_HTTP_PORT_SET}:8080"
    environment:
      APP_PASSWORD: ${APP_PASSWORD}
    restart: unless-stopped
```

### `apps/<key>/variables.json`

Declare at least one installable edition. The version values appear in the App Store install dialog.

```json
{
  "edition": [
    {
      "dist": "community",
      "version": ["latest"]
    }
  ]
}
```

Optional `.env.<profile>` files add deployment profiles. A profile with `W9_DATABASE_MODE=external` is recognized as an external-database profile.

## Refresh and Verify

After adding or changing a local application, open **App Store**, enable **Custom applications**, and use the refresh action. Refresh validates `catalog/*.json` and matching `apps/<key>/` directories, then rewrites `manifest/app-store-manifest.json` atomically.

If one application is invalid, valid applications remain available and the refresh result reports the skipped key. If every application is invalid, the existing manifest is retained. Check that the file names match, all three required files exist, `variables.json` contains a valid `edition`, and `catalog/<key>.json` is valid JSON.

The default root follows `WEBSOFT9_DATA_ROOT`. To use another location, set `WEBSOFT9_LOCAL_APP_STORE_ROOT`; the same path is used by listing, refresh, and installation APIs.
